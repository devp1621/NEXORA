# Nexora_Student_Career_Website
# Nexora  **Your Potential, Your Next Frontier**  Nexora is a student career-profile and skill-gap website. Students enter education, skills, projects, certifications, experience, and achievements, choose a target career, and compare their profile with that career’s listed skills. The app turns the comparison into prioritized learning gaps and a roadmap.  > Career requirements are illustrative hackathon examples. They are not official industry standards or a hiring assessment.  ## What the website includes  - **Welcome page** with an overview, sample content, and links to sign in, create an account, or continue as a guest. - **Student profile builder** for education, technical skills and proficiency, projects, certifications, experience, and achievements. - **Career explorer** with nine editable example career profiles and profile comparisons. - **Dashboard** with the selected career analysis, skill coverage, and report download/print options. - **Skill-gap view** grouping matched, in-progress, and missing skills, with priorities. - **Learning roadmap** based on the selected career requirements, with progress tracking. - **Career chat assistant** that answers using the current profile analysis. It uses rule-based responses by default and can use Anthropic when configured. - **Search palette** for pages and careers, opened with Ctrl+K or Cmd+K. - **Guest mode** saving profile and progress in browser storage; account mode saves state on the server.  ## How the analysis works  Career skill coverage is calculated as **matched required skills ÷ total required skills × 100**.  A skill is matched when its reported proficiency is intermediate or advanced. Beginner skills are shown as in progress; absent skills are shown as missing. Proficiency depth is reported separately and does not change coverage. Skill names are normalized using editable aliases in the skill catalog.  This result reflects the profile data and the project’s example datasets. It does not predict employability or guarantee that a student meets an employer’s requirements.  ## Technology  - **Frontend:** React 19, JavaScript modules, and plain CSS; bundled with esbuild. - **Backend:** Python, Starlette, Pydantic, and Uvicorn. - **Local accounts and saved state:** SQLite by default. - **Optional database:** MongoDB through PyMongo. - **Optional AI:** Anthropic API for enhanced recommendations and chat. The API key stays on the backend.  The backend serves the built frontend from `frontend/dist`, so the normal run flow uses one local server.  ## Run Nexora  ### Quick start  Requires Python 3.9 or newer. From the extracted project folder:  - **Windows:** double-click `start.bat`, or run `python start.py`. - **macOS/Linux:** run `python3 start.py`.  The launcher checks required Python packages, installs missing runtime packages with pip, starts the server on an available port beginning at 8000, and opens the site in a browser. Keep the terminal window open while using Nexora; press `Ctrl+C` there to stop the server.  The launcher needs internet access if it must install missing Python packages. The archive includes the built frontend, so Node.js is not required just to run the packaged site.  ### Manual backend start  From the project folder:  ```bash python -m pip install -r backend/requirements.txt cd backend python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 ```  Then open [http://localhost:8000](http://localhost:8000).  ### Rebuild the frontend  Node.js and npm are needed only when changing frontend source files:  ```bash cd frontend npm install npm run build ```  The build writes the generated site to `frontend/dist`. Restart the backend after rebuilding.  ## Accounts and saved data  By default, the backend creates a local SQLite database at `backend/nexora_local.db`. This enables sign-up, sign-in, and server-side state saving without installing a separate database. The database file is excluded by `.gitignore`.  To disable accounts and run in guest mode only, set:  ```env NEXORA_LOCAL_DB=off ```  To use MongoDB instead, copy `backend/.env.example` to `backend/.env` and set `MONGODB_URI` (and optionally `MONGODB_DB`). Install the listed backend requirements, ensure the MongoDB server or Atlas cluster is reachable, and restart the app. If MongoDB cannot connect, account features are unavailable; the health endpoint reports the status.  Guest profile, career, roadmap progress, and chat history are stored in that browser’s local storage. Signed-in profile state, career choice, progress, and chat history are stored by the backend.  ## Optional AI configuration  Copy `backend/.env.example` to `backend/.env` and set `ANTHROPIC_API_KEY` to enable AI-enhanced recommendations and chat. The key is read by the backend and is not included in frontend code. Without the key, recommendations and chat use deterministic rule-based behavior.  The project documentation says the AI integration has mocked test coverage but has not been validated against the live Anthropic API. Core skill analysis does not depend on AI.  ## API overview  | Method | Path | Purpose | | --- | --- | --- | | `GET` | `/api/health` | Server, career catalog, AI, and account-storage status | | `GET` | `/api/careers` | Career profiles and requirements | | `POST` | `/api/analyze` | Calculate skill coverage, matches, gaps, and roadmap | | `POST` | `/api/recommendations` | Return recommendations, with AI enhancement when configured | | `POST` | `/api/chat` | Answer a question using the submitted profile analysis | | `POST` | `/api/auth/register` | Create an account | | `POST` | `/api/auth/login` | Sign in | | `POST` | `/api/auth/logout` | Sign out | | `GET` | `/api/auth/me` | Check the current session | | `GET` / `PUT` | `/api/state` | Load or save signed-in profile and progress |  API errors use a JSON object with an error code, message, and optional details.  ## Data and known limitations  - Career and skill catalogs are editable examples, not validated labor-market standards. - Skills are self-reported. Project technologies are recorded as profile evidence, not independently verified. - Local SQLite is a single-machine database. Use a managed MongoDB deployment when multiple app instances or shared server access are needed. - The project does not include email verification or password reset. - Estimated learning effort is approximate. - The live Anthropic API path and account flows against a real MongoDB deployment require configuration and have not been confirmed by the included project materials.  ## License  No license file was present in the supplied project archive.
